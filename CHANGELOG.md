# Changelog

All notable changes to this project are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

> **How releases work:** versions are **derived from the git tag** (e.g. `v2.0.2`),
> not hardcoded in source files. The `[Unreleased]` section below collects changes
> for the next release. Each tag push also gets a fresh entry generated by the
> `softprops/action-gh-release` `generate_release_notes: true` step.

## [Unreleased]

### Changed

- **Versions are no longer hardcoded in source.** All `package.json`, `friday.rb`,
  and `friday.json` files now have a placeholder `0.0.0-private` and are stamped
  at release time from the git tag. No more `bump` step, no more 11 files to
  keep in sync. `scripts/build.ts` falls back to `"dev"` when no `FRIDAY_VERSION`
  is set, matching the source-mode fallback in `cli/src/index.tsx`.
- CI guard: a step fails the build if any `package.json` under `packages/` has a
  version other than `0.0.0-private` (prevents accidental re-introduction of drift).
- Removed `scripts/bump.ts` (replaced by the tag-driven pipeline).
- `npm-publish` job now runs `bun install --frozen-lockfile` before rebuilding the
  launcher (real bug — would have failed on a fresh runner).
- Removed unused `shasums` artifact download from `npm-publish` (publish.ts fetches
  SHAs from GitHub Releases at runtime).
- `packaging/friday-code/package.json`: added `engines.node: ">=18"`.

### Fixed

- Local `bun run scripts/build.ts` without `FRIDAY_VERSION` no longer stamps the
  binary with `"0.0.0-private"` — it stamps `"dev"`.

## [2.0.2] — 2026-06-18

### Changed

- Release pipeline: unified the three matrix jobs (`build`, `build-musl`, `build-win-arm64`)
  into a single 8-target matrix with stability groups. Stable failures block the release;
  musl + Windows ARM64 are best-effort.
- Extracted the ~60-line inline npm publish bash to `scripts/publish.ts`. Adds idempotency
  for retry, plus auto-update of the Homebrew tap (`katipally/homebrew-tap`) and Scoop
  bucket (`katipally/scoop-bucket`) via PRs.
- Added `scripts/version.ts` (derives VERSION + TAG from the trigger).
- `npm-publish` job is now gated by a manual `release` GitHub Environment so you click
  *Approve* before anything goes to npm.
- Launcher npm package is rebuilt in the `npm-publish` job (not tied to whichever native
  runner happened to upload it).
- Dependabot: groups Bun + OpenTUI, Biome + TypeScript, and runtime deps into single PRs.
- `RELEASING.md` documents the new auto flow.

## [2.0.0] — 2026-06-18

First public, open-source release of the rewritten Friday Code — a terminal AI coding agent
built on OpenTUI (Solid) with a hand-rolled, zero-SDK multi-provider engine.

> Note: this `2.0.0` supersedes an unrelated earlier `1.x` line that shipped under the same npm
> name. It is a fresh codebase; treat it as the first stable release.

### Added

- Animated, mouse-first TUI with a mascot, modes (`plan`/`default`/`accept-edit`/`yolo`), and a
  responsive layout.
- Agentic loop with streaming, tool-calling, human-in-the-loop approval, and context
  auto-compaction.
- Multi-provider engine (Anthropic, Google Gemini, and an OpenAI-compatible adapter covering
  OpenAI, OpenRouter, Groq, DeepSeek, xAI, Together, Ollama, and more) with prompt caching and a
  models.dev catalog snapshot.
- Tools: file read/write/edit/multi-edit/apply-patch, ls/glob/grep, bash, web fetch/search,
  ask_user, skills, sub-agent tasks, todos, memory, notebook editing, tool search, LSP
  (hover/definition/symbols), background tasks, cron schedules, and git worktrees.
- Sessions with `bun:sqlite` persistence, parallel background sessions, checkpoints/rewind/redo,
  and resume (`-s` / `-c`).
- LSP grounding, Claude-Code-parity hooks, MCP client (stdio + streamable-HTTP), and `/commit`.
- Self-contained binaries for macOS (arm64/x64), Linux (x64/arm64), and Windows (x64), distributed
  via npm, Homebrew, Scoop, a curl installer, and GitHub Releases.
- `friday --version` / `friday --help`.

### Security

- Compiled binaries are built with `--no-compile-autoload-bunfig`, so they don't read or execute
  `preload` scripts from a working-directory `bunfig.toml`.
